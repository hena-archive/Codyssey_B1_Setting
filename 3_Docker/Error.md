## Error. `docker exec`의 `-i`와 `-t` 옵션 차이

### 문제

`docker exec -it <container> bash`를 자주 사용했지만, `-i`와 `-t`가 각각 어떤 역할을 하는지 명확하게 이해하지 못했다.

특히 `-i`만 사용하거나 `-t`만 사용했을 때 어떤 차이가 발생하는지 궁금하였다.

---

### 원인

`-i`와 `-t`는 서로 다른 기능을 수행한다.

| 옵션 | 역할 |
| :--- | :--- |
| `-i` (`--interactive`) | 표준 입력(STDIN)을 열어 키보드 입력을 받을 수 있도록 한다. |
| `-t` (`--tty`) | 가상 터미널(TTY)을 생성하여 일반 터미널 환경처럼 동작하도록 한다. |

실무에서는 대부분 두 옵션을 함께 사용하기 때문에 각각의 역할을 체감하기 어려웠다.

---

### 확인 과정

#### 1. `-i`만 사용

```bash
docker exec -i my-web bash
```

실행 결과

```text
(프롬프트가 보이지 않음)
```

하지만 명령을 입력하면 정상적으로 실행된다.

```text
pwd
/
```

```text
ls
bin
boot
dev
...
```

즉,

- 입력은 가능하다.
- 프롬프트와 같은 터미널 환경은 제공되지 않는다.

---

#### 2. `-t`만 사용

```bash
docker exec -t my-web bash
```

실행 결과

```text
바로 종료되거나 입력이 되지 않음
```

TTY는 생성되지만 입력(STDIN)이 연결되지 않아 정상적인 셸을 사용할 수 없다.

---

#### 3. `-it` 사용

```bash
docker exec -it my-web bash
```

실행 결과

```text
root@4f2e91a0c8b3:/#
```

일반적인 리눅스 터미널처럼 사용할 수 있었다.

```bash
pwd
ls
cd /
exit
```

모든 명령이 정상적으로 수행되었다.

---

### 해결

`-i`와 `-t`를 함께 사용하면 입력과 터미널 환경이 모두 제공된다.

| 옵션 | 제공 기능 |
| :--- | :--- |
| `-i` | 키보드 입력(STDIN) |
| `-t` | 터미널(TTY) 환경 |

따라서 컨테이너 내부에서 Bash 또는 Sh 셸을 사용할 때는 다음과 같이 실행하는 것이 일반적이다.

```bash
docker exec -it <container> bash
```

또는

```bash
docker exec -it <container> sh
```

---

### 정리

- `-i` : 키보드 입력을 받을 수 있도록 한다.
- `-t` : 일반 터미널과 같은 셸 환경을 제공한다.
- `-it` : 두 기능을 함께 활성화하여 컨테이너 내부를 일반 리눅스 터미널처럼 사용할 수 있다.
